# F-066 · 冲突判定权留在本仓，参数层只执行

- **状态**: Accepted
- **日期**: 2026-09-06

## 背景

P2-1 规定冲突"判定"以本仓检测为准。存在另一种设计：把冲突判定交给 M1 的参数层（delta 规则自带"新值覆盖旧值"语义）。

## 决策

判定留在本仓 card-evolution（supersession 检测）；参数层只执行 forget(旧)+write(新)。此边界写进 GOVERNANCE §2，不得以优化名义上移。

## 后果（why 这么定）

- M1 的 delta 更新规则在冲突消解评测中**已判负**——参数层的覆盖语义是"最后写赢"，不是"判定谁对"。用执行器做判定器是用错工具。
- 本仓的判定有 LLM 抽取质量门（R1-R5）、embedding 相似度等本仓上下文，参数层拿不到这些信号。
- 参数层保持"哑执行"也简化了它的测试面：执行正确性可以纯代数验证。
