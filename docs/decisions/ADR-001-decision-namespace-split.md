# ADR-001 · 决策记录命名空间分离：冻结 F-编号，启用 ADR- 前缀

- **状态**: Accepted
- **日期**: 2026-09-07
- **修订**: `docs/decisions/README.md`、GOVERNANCE §6

## 背景

本仓存在两套同前缀编号：

1. **上游 feature/fix 标记**：代码注释中的 F-053（统一级联）、F-055、F-056、
   F-058、F-059、F-060（HyDE）、F-064（external-chat provenance）、F-072
   （prompt-injector）、F-082、F-088 等——随上游 sync 持续增长；
2. **本仓决策记录**：`docs/decisions/F-061~F-075`——与上述空间重叠。

已发生三次实撞：F-064 双义（上游 external-chat vs 本仓相对零阈值）；F-072
三撞（上游 prompt-injector、trace 二期提案、首跳 env 表面——后者被迫让号
F-074）；并发会话双占 F-072/F-073（靠让号 + rebase 解决，成本一次比一次高）。

## 决策

1. **F-061~F-075 冻结**为遗留块，文件与编号不变（历史引用、commit message
   均有效）；索引标注"冻结"。
2. **新决策从 `ADR-001` 起**，文件名 `ADR-<NNN>-<slug>.md`，与上游
   feature-flag 空间彻底分离。
3. GOVERNANCE §6 措辞同步："决策记录（ADR- 前缀；F-061~F-075 为冻结遗留块）"。
4. 代码注释中的遗留 F- 标记**不在本 ADR 范围内清洗**——那是上游的编号体系，
   随上游 sync 自然演进。

## 后果

- 并发会话不再可能撞号（ADR- 空间只有决策记录使用）。
- F-064 等既有双义保留为已知历史，靠链接文件名消歧（引用 ADR 时必须带文件
  链接而非裸编号）。
- 起始编号从 ADR-001 重新计数，不复用 F- 语义。
