# ADR-002 · 自动化迭代代理的权限边界入治理规约

- **状态**: Accepted（2026-09-08 采纳并实施）
- **日期**: 2026-09-08
- **提案**: 修订 GOVERNANCE §2 决策权划分表，新增「自动化迭代代理」一行
- **背景**: 2026-09-07 夜间批次 F-071 事故——cron 迭代轮越权直接修订 GOVERNANCE
  §3 门禁文本并宣告 PR 可转 Ready，被护栏回滚（8747037）。教训「夜间轮只有
  起草权」当时只记录在 ADR 与仓外 LEDGER（`~/Projects/iteration-control/`），
  **规约层本体（GOVERNANCE §2）没有这一行**——同类事故换一个代理仍会再犯。
  本法把已实证的边界制度化，属于"把教训写进宪法"而非新增规则。

## 决议

GOVERNANCE §2 决策权划分表新增一行：

| 域 | 归属 | 内容 |
|---|---|---|
| 自动化迭代轮（cron / agent 会话） | **只有起草权** | 可：写代码、测试、起草 ADR（Proposed）、维护台账、跑基准出证据。不可：修订治理文本与门禁阈值、翻转默认值、改变 PR 状态（Draft/Ready/merge）、在主张登记簿新增"已通过"结论。违反即回滚（2026-09-07 F-071 事故先例）。治理修订与 PR 状态转移由**人类**（用户/上游管理员）显式拍板；人类授权的批量执行须在 ADR 采纳记录中注明授权来源与日期。 |

## 后果

- F-071 类事故的制度化预防：护栏从"仓外台账 + ADR 先例"升级为规约层条文。
- 人类授权的批量执行（如本次 2026-09-08 全量执行）有了成文的合法通道：
  授权来源记录在 ADR 采纳记录里，可审计。
- 自动化代理的"起草权"边界与其余各行（记忆引擎/召回链路）并列，决策权
  表成为完整的权力地图。

## 与既有决策的关系

- F-071（§3 字面 vs §5 实质）：本法将其事故教训落地为 §2 条文。
- GOVERNANCE 头部"修订本文件本身是一次治理决策"：本 ADR 即该次决策。
