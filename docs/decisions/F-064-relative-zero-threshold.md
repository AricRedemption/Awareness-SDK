# F-064 · 首跳命中判据沿用 M1 相对零阈值

- **状态**: Accepted
- **日期**: 2026-09-06

## 背景

参数化 recall 需要区分"真绑定"与"fp32 残留"（forget 后 |qF|~1e-7 仍指向被擦除的值）。M1 已在 ParametricMemory 中实现并测试了相对零阈值：`|qF| ≤ 1e-5·|F|` → 无记忆。

## 决策

本仓不新造判据。JS 首跳直接采信 broker recall 返回的非空值（阈值判定在 M1 层已完成）；Python 侧 recall 只过滤 value=null 的条目。

## 后果

- 判据的正确性责任在 M1（它有测试覆盖），本仓不做二次发明。
- 若 M1 调整阈值常数，本仓无需改代码——这是把判据放 M1 的最大收益。
- 缺点：本仓测试只能验证"null 过滤"行为，阈值语义依赖 M1 的测试背书。
