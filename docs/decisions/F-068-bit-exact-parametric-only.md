# F-068 · bit-exact 保证只覆盖参数化层

- **状态**: Accepted
- **日期**: 2026-09-06

## 背景

会话迁移的自然期望是"迁移后一切如初"。但本仓记忆有两层：参数化层（F, z 张量，可 bit-exact 快照）与 SQLite 情景层（E5 向量 + FTS5 索引，无法 bit-exact——向量重嵌入、索引重建都有浮点与实现差异）。

## 决策

bit-exact 承诺**只覆盖参数化层**（state_bytes 与逐绑定 recall 逐位一致，单测锁定）。SQLite 情景层明确不在保证内，两层各自独立导出（参数化走本模块，SQLite 走 client.export_memory_package）。文档写死此边界。

## 后果（why 这么诚实）

- 过度承诺（"完整迁移"）会在 SQLite 层首次浮点差异时变成用户可复现的"谎言"——M1 RESULTS.md 的 RETRACTED 教训就是数字主张失控的代价。
- 边界清晰反而给 SQLite 情景层的迁移留出独立演进空间（未来若做语义层迁移，立新决策，不动本条）。
- 测试的"错误会话导入 → chance 水平"用例锁定了失败模式的可观测性。
